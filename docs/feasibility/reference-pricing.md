## Normalization proposal

Represent decimal rates with explicit currency and units; prefer fixed-point or exact decimal/rational arithmetic in Go, rounding at display boundaries. Preserve raw source fields and version of each billing transformation. Separate canonical model identity from exact offered route and tariff schedule. A price record includes source URL, retrieval timestamp, effective interval if known, model/version, route/endpoint, price type (documented route tariff / mapped proxy / user estimate), billing categories, duration/context/peak conditions and unknown fields. Do not mix categories from different providers to fabricate one complete tariff.

Use disjoint billed token categories: uncached input, cache read, each separately billed cache-write tier, output including reasoning where documented, and separate reasoning only where independently charged. Normalize provider-specific inclusive totals before calculation; reject negative or inconsistent counts. Additional request fees require explicit request count, and tier pricing requires context information at request level. Unknown applicable rates or conditions mean unknown total, not zero. Model time-dependent schedules as provider/plan/route/model-specific weekday and UTC intervals, preserving effective dates, promotion expiration and boundary semantics. Convert to local time for display only, with daylight-saving awareness. Confirmed MVP simplification: global Settings expose Peak Pricing On/Off (default Off, i.e. Off-Peak) and Context Size (default Small, i.e. the lowest documented context tariff tier). These are explicit reference-cost scenario assumptions, not claims about actual request timing or context length. Do not automatically choose a tariff from the current clock or aggregate token volume. Map the chosen context tier to each model/route's documented thresholds and rates; show those thresholds and offer further tiers where applicable. For a documented flat tariff, mark the irrelevant setting as not applicable and use its single rate; if a selected applicable tier/rate is unknown, report unknown rather than silently substituting another rate. Preserve promotion expiry dates and warn when a stored tariff has expired, but do not automatically replace, exclude or modify the stored reference price solely because of expiration. Label expired-price estimates as historical/stale, not confirmed current charges. Record the effective settings and warnings with each evaluation. Request-level sizes and timing remain necessary for any later actual billing calculation. If the tariff does not document the selected tier's applicability or rate, leave the reference cost unresolved rather than guessing. Test scenario-to-tariff mapping independently of the clock and aggregate token counts, including expired-price warnings and flat-rate routes. Keep AI-credit units distinct from legacy request multipliers. A known zero or documented inapplicable category is distinct from missing data. Reference profiles describe a common hypothetical workload, not predicted model consumption. Compare only compatible currencies/volumes/semantics. Record explicit exchange rate/date if conversion is later supported.

Synthetic examples (not market rates):
- 400,000 uncached input at $1/M + 500,000 cache read at $0.10/M + 100,000 output at $4/M = $0.85. If the 100,000 output includes 30,000 reasoning tokens, do not add them again.
- If 900,000 total prompt tokens include 500,000 reads, normalize to 400,000 uncached input before billing, where provider semantics establish this partition.
- If cache write usage is positive and its applicable rate is missing, the full reference cost is unknown. If usage is explicitly zero, that category contributes zero.
- RTK: for a baseline of 400,000 uncached input, 50% optimizable share and 20% reduction of that share, the estimate is 360,000 uncached input. Do not reduce measured post-optimization tokens or other categories automatically.

## Subscription and user interface boundaries

Show reference workload costs separately from observed charges and quota usage. A $0 balance charge within Go allowance is not evidence of free or unlimited usage. Documented allowance metadata can inform future optimization, but quota conversion/optimization is outside the MVP; no claim of actual legacy plan cost. Never enable paid overage or switch routes automatically. User-selected price sources, explicit manual reference rates, and offline evaluation remain possible; do not silently substitute sources after failures. Keep quality rankings independent of prices and use only comparable known cost evidence for qualifying recommendations.
